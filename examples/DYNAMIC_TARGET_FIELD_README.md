# Динамическое поле "Целевое поле" в зависимости от "Целевой таблицы"

## Описание функционала

Поле "Целевое поле" теперь является селектом с динамическими опциями в зависимости от выбранной "Целевой таблицы":

### Логика работы:

1. **Не указано** → селект заблокирован
2. **События (events)** → опции: "Результат матча" (result), "Доп.результат" (dop_result)
3. **События команд (event_teams)** → опции из таблицы `team_action_types` (поле `name`, значение `id`)
4. **События игроков (event_players)** → опции из таблицы `action_types` (поле `name`, значение `id`)

## Что изменено

### 1. Frontend (pages/parser/[id]/edit.vue)

**HTML изменения:**
- Поле "Целевое поле" преобразовано из `input` в `select`
- Добавлен обработчик `@change="onTargetTableChange(field)"` для целевой таблицы
- Селект заблокирован когда не выбрана целевая таблица
- Динамические опции в зависимости от выбранной таблицы

**JavaScript изменения:**
- Добавлены `actionTypes` и `teamActionTypes` для хранения данных
- Метод `loadSelectData()` для загрузки данных селектов
- Метод `onTargetTableChange(field)` для сброса целевого поля при изменении таблицы
- Загрузка данных селектов при инициализации

### 2. Backend

**Новые контроллеры:**
- `ActionTypeController` - для загрузки типов действий игроков
- `TeamActionTypeController` - для загрузки типов действий команд

**Новые API endpoints:**
- `GET /admin/action-types` - список типов действий игроков
- `GET /admin/team-action-types` - список типов действий команд

**Маршруты:**
- Добавлены в `routes/api.php` с middleware `auth:sanctum` и `admin`

## Как это работает

1. **При загрузке страницы:**
   - Загружаются данные для селектов (`actionTypes`, `teamActionTypes`)
   - Загружается шаблон парсера

2. **При изменении целевой таблицы:**
   - Сбрасывается значение целевого поля
   - Обновляются опции в селекте целевого поля

3. **При выборе целевого поля:**
   - Сохраняется ID для `event_teams` (из `team_action_types`) и `event_players` (из `action_types`)
   - Сохраняется строковое значение для `events`

## Преимущества

- **Удобство**: Пользователь видит доступные опции вместо ввода вручную
- **Точность**: Исключены ошибки в названиях полей
- **Консистентность**: Все пользователи используют одинаковые названия
- **Валидация**: Невозможно выбрать несуществующее поле

## Что нужно проверить

1. **Frontend**: Селект корректно обновляется при изменении таблицы
2. **Backend**: API endpoints возвращают корректные данные
3. **Сохранение**: Значения корректно сохраняются в базе данных
4. **Загрузка**: При редактировании значения корректно загружаются
