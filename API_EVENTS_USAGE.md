# API Events - Правильное использование

## Основные параметры запроса

### Обязательные параметры для ограничения результатов:

1. **`per_page`** - количество записей на страницу (по умолчанию: 10, максимум: 100)
2. **`page`** - номер страницы (по умолчанию: 1)

### Параметры фильтрации:

#### Временные фильтры:
- **`show`** - тип фильтрации по дате:
  - `1` - события с датой >= сегодня (по умолчанию)
  - `2` - события с датой <= сегодня (прошедшие)
  - `3` - события на сегодня
  - `4` - все события без ограничений по дате

- **`date_from`** - фильтр по начальной дате (формат: YYYY-MM-DD)
- **`date_to`** - фильтр по конечной дате (формат: YYYY-MM-DD)

#### Региональные фильтры:
- **`region_id`** - ID региона (по умолчанию: 1)
- **`show_home`** - показывать только домашние события:
  - `1` - только события региона
  - `2` - события с командами из региона
- **`all_regions`** - игнорировать фильтр по региону (показывать события всех регионов):
  - `1` или `true` - игнорировать фильтр по региону
  - `0` или `false` - применять фильтр по региону (по умолчанию)

#### Фильтры по сущностям:
- **`sport`** - slug вида спорта
- **`sport_id`** - ID вида спорта
- **`club`** - slug клуба
- **`club_id`** - ID клуба
- **`arena`** - slug арены
- **`arena_id`** - ID арены
- **`competition_id`** - ID соревнования
- **`gender_id`** - ID пола

#### Другие фильтры:
- **`is_active`** - активные события (по умолчанию: 1)
- **`tickets`** - фильтр по билетам:
  - `free` - только бесплатные
  - `paid` - только платные
- **`q`** - поисковый запрос

## Примеры правильных запросов:

### 1. Получить будущие события (по умолчанию):
```
GET /api/v1/events?per_page=20&page=1
```

### 2. Получить события на сегодня:
```
GET /api/v1/events?per_page=20&page=1&show=3
```

### 3. Получить прошедшие события:
```
GET /api/v1/events?per_page=20&page=1&show=2
```

### 4. Получить все события без ограничений по дате:
```
GET /api/v1/events?per_page=20&page=1&show=4
```

### 5. Получить события конкретного клуба:
```
GET /api/v1/events?per_page=20&page=1&club=zenit
```

### 6. Получить события конкретного вида спорта:
```
GET /api/v1/events?per_page=20&page=1&sport=football
```

### 7. Получить события в диапазоне дат:
```
GET /api/v1/events?per_page=20&page=1&date_from=2024-12-01&date_to=2024-12-31
```

### 8. Получить события конкретной даты:
```
GET /api/v1/events?per_page=20&page=1&date_from=2024-12-07
```

### 9. Получить события с поиском:
```
GET /api/v1/events?per_page=20&page=1&q=Зенит
```

### 10. Получить события серии:
```
GET /api/v1/events?per_page=20&page=1&series_id=123
```

### 11. Получить события серии всех регионов:
```
GET /api/v1/events?per_page=20&page=1&series_id=123&all_regions=1
```

## Важные замечания:

1. **Всегда указывайте `per_page`** - это ограничивает количество возвращаемых записей
2. **Используйте `page` для пагинации** - не пытайтесь получить все записи сразу
3. **По умолчанию возвращаются только будущие события** - используйте `show=4` для получения всех событий
4. **Максимальное значение `per_page` = 100** - большие значения будут автоматически ограничены
5. **Для получения большого количества записей используйте `get_events`** - но не более 1000

## Защита от больших запросов:

API автоматически ограничивает:
- `per_page` до максимум 100 записей
- `get_events` до максимум 1000 записей
- Общее количество записей до максимум 10000

Если запрос пытается получить больше записей, API автоматически ограничит результат и запишет предупреждение в лог.
