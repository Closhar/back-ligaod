# Универсальный парсер - Документация

## Описание

Универсальный парсер - это система для автоматического извлечения данных с веб-страниц и их интеграции в базу данных. Система позволяет создавать настраиваемые шаблоны парсинга для различных типов страниц.

## Возможности

- Создание и редактирование шаблонов парсинга
- Поддержка CSS и XPath селекторов
- Настройка условий применения шаблонов
- Автоматическое извлечение и обработка данных
- Интеграция с существующими таблицами БД
- Тестирование шаблонов перед применением
- Логирование всех операций парсинга

## Структура базы данных

### Таблица `parser_templates`
- `id` - Уникальный идентификатор
- `name` - Название шаблона
- `description` - Описание назначения
- `url_pattern` - Регулярное выражение для URL
- `conditions` - Условия применения (JSON)
- `is_active` - Активен ли шаблон

### Таблица `parser_fields`
- `id` - Уникальный идентификатор
- `parser_template_id` - Ссылка на шаблон
- `name` - Название поля
- `selector` - CSS/XPath селектор
- `selector_type` - Тип селектора (css/xpath)
- `data_type` - Тип данных
- `extraction_rules` - Правила извлечения (JSON)
- `target_table` - Целевая таблица БД
- `target_field` - Целевое поле БД
- `update_strategy` - Стратегия обновления
- `is_required` - Обязательное поле
- `order` - Порядок обработки

### Таблица `parser_logs`
- `id` - Уникальный идентификатор
- `parser_template_id` - Ссылка на шаблон
- `url` - URL обработанной страницы
- `raw_data` - Сырые данные
- `parsed_data` - Обработанные данные
- `errors` - Ошибки парсинга
- `status` - Статус операции
- `records_created` - Количество созданных записей
- `records_updated` - Количество обновленных записей

## Создание шаблона

### 1. Основная информация
- **Название**: Описательное название шаблона
- **Описание**: Детальное описание назначения
- **URL паттерн**: Регулярное выражение для определения подходящих страниц

### 2. Условия применения
Условия определяют, когда шаблон должен применяться:
- **Обязательно присутствует**: Элемент должен существовать на странице
- **Содержит текст**: Элемент должен содержать указанный текст
- **Равно значению**: Элемент должен точно соответствовать значению

### 3. Поля для парсинга
Каждое поле настраивается отдельно:
- **Название**: Уникальное имя поля
- **Селектор**: CSS или XPath селектор для поиска элемента
- **Тип данных**: text, number, date, url
- **Целевая таблица**: events, event_teams, event_players
- **Целевое поле**: Название поля в целевой таблице
- **Стратегия обновления**: insert, update, upsert

### 4. Правила извлечения
- **trim**: Удаление лишних пробелов
- **replace**: Замена текста
- **regex**: Извлечение по регулярному выражению
- **lowercase/uppercase**: Изменение регистра

## Пример шаблона для хоккейного матча КХЛ

### Настройки шаблона
- **Название**: Парсер хоккейных матчей КХЛ
- **URL паттерн**: `/online\.khl\.ru\/online\/\d+\.html/`
- **Условие**: Страница должна содержать текст "Окончание игры"

### Поля для парсинга

#### 1. Результат матча
- **Селектор**: `.game-result, .score, [class*="result"]`
- **Целевая таблица**: events
- **Целевое поле**: result
- **Правила**: Замена " – " на ":"

#### 2. Статистика команд
- **Селектор**: body (с regex для извлечения)
- **Целевая таблица**: event_teams
- **Поля**: shots, goals, faceoffs, hits, penalties и др.

#### 3. События игроков
- **Селектор**: body (с regex для извлечения)
- **Целевая таблица**: event_players
- **Поля**: время, имя, команда, тип события

## Использование

### 1. Создание шаблона
1. Перейдите в админку → Парсер
2. Нажмите "Создать шаблон"
3. Заполните все необходимые поля
4. Сохраните шаблон

### 2. Тестирование шаблона
1. Выберите шаблон в списке
2. Нажмите кнопку "Тест"
3. Введите URL для тестирования
4. Просмотрите результаты

### 3. Применение парсера
1. Выберите шаблон в списке
2. Нажмите кнопку "Парсить"
3. Введите URL для парсинга
4. Дождитесь завершения операции

## API Endpoints

### Получение списка шаблонов
```
GET /admin/parser
```

### Создание шаблона
```
POST /admin/parser
```

### Тестирование шаблона
```
POST /admin/parser/{id}/test
```

### Применение парсера
```
POST /admin/parser/{id}/parse
```
